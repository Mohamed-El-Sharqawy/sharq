## Decisions & deviations

- **Renaming a CI job requires a branch-protection update in the same session (2026-10-18, rows 10–11 session):** task 8 renamed the quality job to `install -> lint -> line-count -> typecheck -> unit -> build` but protection still required the old `… -> unit` name, so PR #2 hung on "Expected — Waiting for status to be reported" while both real checks were green. Standing rule: any CI job-name change updates `required_status_checks` contexts immediately (gh api PATCH …/branches/main/protection/required_status_checks).
- **`packages/ui` state components live in one `states.tsx` (2026-10-18, row 11):** three tiny presentational components share a file + spec (`states.test.tsx`); they grow into separate files only if one crosses the refactor threshold. shadcn registry items keep their per-file convention (button.tsx).

- **shadcn style base-nova runs on Base UI + `cn` package (2026-10-18, task 9):** the 2026 registry default is not Radix-era shadcn — components import `@base-ui/react/*` (1.9.0) and `cn` from the `cn` package (0.5.0), no `lib/utils.ts`, no clsx/tailwind-merge. SPEC §14.1's patch list is unaffected (it names components, not primitives). Catalog dropped clsx/tailwind-merge; re-add via catalog if a future registry item imports them.
- **RTL patch policy, two levels (2026-10-18, task 9):** token-level physical→logical fixes (`pl-/pr-`→`ps-/pe-`) are applied IN PLACE in `packages/ui/src/components/*` (vendored source is ours; logical is correct in LTR too) with a `SPEC §14.1 RTL patch` comment; behavioral flips (chevrons, side mapping, week order) become wrappers in `packages/ui/src/rtl/` — the only lint-exempt area. Regenerating a component via the CLI re-applies its patch (grep duty). Protocol + §14.1 checklist: `packages/ui/src/rtl/README.md`.
- **shadcn CLI installs deps into the running project, not the alias target (2026-10-18, task 9):** `add` from apps/web wrote `cn@^0.5.0` into web's package.json while the component landed in packages/ui. Standing pattern: pre-add every registry dep to `@sharq/ui` via catalog BEFORE running `add`, then revert anything the CLI pinned into web.
- **`packages/ui` component-test runner decided (2026-10-18, task 9):** Vitest + Testing Library + jsdom inside the package (TESTING §2.1 scopes component tests to that stack); catalog versions identical to web's. Wiring (test script + vitest.config.ts) lands with row 10's red commit per the task-4 convention — never a test script without tests.
